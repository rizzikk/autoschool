# Публикация проекта

Приложению нужны две вещи: сервер PocketBase и собранный клиент. Браузер не разрешает странице по
HTTPS обращаться к серверу по HTTP, поэтому сервер обязан отвечать по HTTPS.

Ниже основной вариант: всё берётся из git-репозитория, ничего не платится и карта не нужна. Клиент
выкладывает GitHub Pages, сервер запускает Render из того же репозитория.

## Основной вариант: GitHub Pages и Render

### 1. Репозиторий

Создать на GitHub публичный репозиторий `autoschool` (у бесплатных аккаунтов Pages работает только
для публичных) и загрузить в него проект:

```powershell
cd C:\Users\GRUT\DART\autoschool
git init
git add .
git commit -m "Автошкола"
git branch -M main
git remote add origin https://github.com/<логин>/autoschool.git
git push -u origin main
```

### 2. Сервер на Render

В репозитории есть `Dockerfile`, `pocketbase/start.sh` и `render.yaml`. Образ скачивает PocketBase,
кладёт в него `pb_hooks`, при запуске создаёт суперпользователя, поднимает сервер и выполняет
`node setup.mjs --reset`: создаёт таблицы и тестовые данные.

1. Зарегистрироваться на render.com через GitHub.
2. New → Blueprint, выбрать репозиторий `autoschool`, подтвердить план Free и запустить.
3. Дождаться статуса Live. Адрес сервера будет вида `https://autoschool-api.onrender.com`.
4. Проверить: `https://autoschool-api.onrender.com/api/health` отвечает `{"code":200,...}`.

Пароль суперпользователя Render генерирует сам, он виден в Environment сервиса
(`PB_SUPERUSER_PASSWORD`), почта `root@autoschool.test`. Панель администратора: `/_/`.

Ограничения бесплатного плана Render. Сервис засыпает после 15 минут без запросов, первый запрос
после этого идёт около минуты, а потом ещё сколько-то секунд заполняются данные. Файловая система
временная, поэтому после каждого сна и перезапуска база создаётся заново: тестовые данные и три
учётные записи возвращаются, а всё, что добавили руками, пропадает. Для учебной защиты этого хватает,
для настоящей работы нужен тариф с постоянным диском.

### 3. Клиент на GitHub Pages

1. Репозиторий → Settings → Pages → Source: GitHub Actions.
2. Settings → Secrets and variables → Actions → вкладка Variables → New repository variable:
   `API_BASE_URL` = `https://autoschool-api.onrender.com/api` (свой адрес сервера и `/api` в конце).
3. Actions → «Проверка и публикация» → Run workflow. Файл `.github/workflows/deploy.yml` проверяет
   сервер и клиент, собирает приложение и публикует его. Для прямых ссылок workflow кладёт рядом с
   `index.html` копию `404.html`.
4. Адрес приложения: `https://<логин>.github.io/autoschool/`.

### 4. Что проверить после публикации

- Сервер уже проснулся (открыть `/api/health`), потом открыть приложение и войти под тремя ролями
  (почты и пароль в `README.md`).
- Прямая ссылка на отфильтрованный список открывается после входа и после обновления страницы.
- Курсант по ссылке `/users` попадает на экран «Доступ запрещён».
- Создание автомобиля с уже существующим номером показывает ошибку под полем.
- Если сервер недоступен, приложение показывает сообщение и кнопку «Повторить».

## Запасной вариант: платный хостинг PocketBase

Бесплатного тарифа у PocketHost (pockethost.io) больше нет, там платные планы с пробным периодом.
Зато сервер и сайт тогда живут на одном адресе, и база не пропадает.

1. Создать экземпляр, запомнить адрес и создать суперпользователя в панели `/_/`.
2. По FTPS (адрес в личном кабинете, вход как в аккаунт) скопировать содержимое
   `pocketbase/pb_hooks` в каталог `pb_hooks` экземпляра.
3. Собрать клиент `flutter build web --release --dart-define=API_BASE_URL=/api` и скопировать
   `build/web` в каталог `pb_public`.
4. Создать таблицы и данные с компьютера, из каталога `pocketbase/tools`:

   ```powershell
   $env:PB_URL = "https://autoschool.pockethost.io"
   $env:PB_SUPERUSER_EMAIL = "почта суперпользователя"
   $env:PB_SUPERUSER_PASSWORD = "пароль суперпользователя"
   node setup.mjs --reset
   node verify.mjs
   ```

   В конце `verify.mjs` должна быть строка «ИТОГО: успешно 55, ошибок 0».
