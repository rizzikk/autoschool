# Автошкола — информационная система

Итоговый индивидуальный проект. Клиент на Flutter Web, сервер на PocketBase.
Три роли: курсант, инструктор, администратор. Курсант записывается на вождение и
следит за своим прогрессом, инструктор ведёт занятия и экзамены, администратор
управляет всем справочным и учётным.

## Состав

| Каталог | Что внутри |
|---|---|
| `lib/` | клиент: слои `core`, `models`, `repositories`, `domain`, `state`, `forms`, `screens`, `widgets`, `router` |
| `test/` | модульные и виджетные тесты клиента |
| `pocketbase/` | сервер: схема, правила доступа, обработчики, тестовые данные, скрипт проверки, выгрузка схемы в JSON и SQL |
| `config/` | адрес сервера для разработки и пример для публикации |
| `.github/workflows/` | автоматическая проверка и публикация |
| `Dockerfile`, `render.yaml` | запуск сервера на Render (см. `docs/ПУБЛИКАЦИЯ.md`) |

## Запуск для разработки

Нужны Flutter 3.41 (Dart 3.11), PocketBase 0.40 и Node.js 18 или новее для служебных скриптов.

1. Сервер. Подробности и учётные записи — в `pocketbase/README.md`.

   ```bash
   pocketbase superuser upsert root@autoschool.test 'Autoschool123!'
   pocketbase serve --http=127.0.0.1:8090 --hooksDir=pocketbase/pb_hooks
   cd pocketbase/tools && node setup.mjs --reset   # схема и тестовые данные
   node verify.mjs                                  # проверка сервера: 55 проверок
   ```

2. Клиент.

   ```bash
   flutter pub get
   flutter run -d chrome --web-port=5555 --dart-define-from-file=config/dev.json
   ```

   Адрес сервера в коде не зашит. Он передаётся параметром `API_BASE_URL`;
   без него клиент обращается к `/api` того же сайта.

## Сборка и публикация

Приложению нужен сервер по HTTPS: браузер не разрешает странице по HTTPS
обращаться к серверу по HTTP. Есть два способа разместить всё.

**Один сайт.** PocketBase сам отдаёт собранное приложение из каталога `pb_public`,
поэтому приложение и API живут на одном адресе и настройки CORS не нужны.

```bash
flutter build web --release --dart-define=API_BASE_URL=/api
cp -r build/web/* <каталог PocketBase>/pb_public/
```

PocketBase отдаёт `index.html` на любой неизвестный путь, поэтому прямые ссылки на
внутренние экраны (`/lessons?status=done`) и обновление страницы работают.

**Приложение на GitHub Pages, сервер отдельно.** Файл `.github/workflows/deploy.yml`
при каждом изменении ветки `main` проверяет сервер и клиент, собирает приложение
и публикует его. Один раз нужно включить Settings → Pages → Source: GitHub Actions
и задать переменную репозитория `API_BASE_URL` (адрес PocketBase по HTTPS,
например `https://autoschool.example.com/api`).

Пошаговая инструкция публикации (GitHub Pages для клиента, Render для сервера, запасной
вариант с платным хостингом) — в `docs/ПУБЛИКАЦИЯ.md`.

## Параметры сборки

| Параметр | По умолчанию | Назначение |
|---|---|---|
| `API_BASE_URL` | `/api` | адрес сервера |
| `IDLE_TIMEOUT_SEC` | `1800` | выход после бездействия, с |
| `IDLE_WARNING_SEC` | `60` | предупреждение до выхода, с |
| `SESSION_MAX_MIN` | `480` | предельная длительность сессии, мин |
| `API_LOG` | `false` | журнал запросов в консоли |

## Что сделано по заданию

* Десять связанных сущностей: пользователи, категории, курсанты, медицинские справки
  (связь один к одному с курсантом), инструкторы (многие ко многим с категориями), автомобили,
  группы (многие ко многим с курсантами), занятия, экзамены, платежи. Схема — в
  `pocketbase/схема.md`, `pocketbase/pb_schema.json` и `pocketbase/schema.sql`.
* Хранилище за интерфейсом `RecordRepository`: `PocketBaseRepository` для сервера и
  `InMemoryRepository` для тестов и работы без сервера.
* Операции создания, чтения, изменения и удаления для всех сущностей, проверка полей на
  клиенте и на сервере с выводом ошибок под полями формы, связанные записи в карточках и формах.
* Регистрация, вход, сохранение сессии после обновления страницы, обновление токена,
  защита маршрутов и экран «Доступ запрещён», скрытие недоступных элементов интерфейса.
* Поиск, три и более фильтра, сортировка и постраничный вывод выполняет сервер; условия
  хранятся в адресе страницы и работают как прямая ссылка.
* Мягкое удаление с корзиной и восстановлением, окончательное удаление, групповые операции.
* Обработка сети: сервер недоступен, тайм-аут, 400 с ошибками по полям, 409 при конфликте
  расписания, повторная попытка, обновление токена при ответе 401.
* Предметная часть: проверка пересечения занятий по инструктору, автомобилю и курсанту
  (на клиенте и на сервере), прогресс курсанта и допуск к экзамену, запись на вождение со
  свободными интервалами, отчёт.
* Адаптивность от 360 до 1920 пикселей: нижняя панель на телефоне, боковая — на планшете и
  компьютере, таблицы превращаются в карточки.
